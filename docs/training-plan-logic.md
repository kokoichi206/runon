# トレーニング計画の計算ロジック（全決定ルール）

`/training` の練習メニューがどう決まるかの完全な説明。**すべて決定的な計算**（AI/プロンプト・乱数なし）。
同じ入力なら毎回同じ結果になる。コードは `src/server/training/` 配下。

関連: 機能仕様は [spec-training-planner.md](./spec-training-planner.md)、データ取り込みは [garmin-strava-integration.md](./garmin-strava-integration.md)。

---

## 0. 入力（これだけで計画が決まる）

`generatePlan(input)`（`plan.ts`）の入力:

- **走力 `fitness`**（CSVから推定, `fitness.ts`）: 週間距離・最長走・イージーペース・現VDOT
- **レース `race`**: 日付・距離・（任意）目標タイム `goalTimeSec`
- **週間設定 `availability`**: 曜日ごとの「練習可能か `isPracticeDay`」＋「確保時間 `maxMinutes`(分)」
- **週の練習回数 `runsPerWeek`**
- **開始日 `startDate`**（通常は今日）、**スキップ日 `skippedDates`**

### 走力の推定（`fitness.ts`）

| 項目 | 算出 |
|---|---|
| 週間距離 | 直近4週の合計距離 ÷ 4 |
| 最長走 | 直近8週の最長単走 |
| イージーペース | 直近8週の距離加重平均ペース × 1.08 |
| 現VDOT | 直近8週で2km以上の走の **VDOT 最大値**（ベスト走。練習走ベースのため控えめに出る） |

履歴が無い場合の既定値: 週10km / 最長5km / 6:00·km / VDOT null。

---

## A. 頻度（いつ・週何回走るか）— `plan.ts`

1. **可能日** = 「練習可能ON かつ 確保時間>0」の曜日
2. **ロング走の日** = 可能日のうち**最も時間が取れる曜日**（同点は後ろの曜日＝週末寄り）
3. **走る回数** = `runsPerWeek` を、可能日数を上限にクランプ
4. **どの可能日を使うか** = ロング走日を必ず含め、残りは **週内の最小間隔（円環ギャップ）が最大になる組合せ**を全探索で選択（連日を避け回復を確保。同点は確保時間合計が多い方）。`selectRunWeekdays`
5. **quality（ポイント練習）日** = 選ばれた日のうち、ロング走日を除いて最も時間が取れる曜日
6. 選ばれなかった可能日・非可能日・スキップ日 = **休養**

---

## B. 期分け（週ごとのフェーズ）— `plan.ts`

- テーパー週数 = `clamp(round(総週数×0.15), 1, 3)`（総週数<4 は 0〜1）
- 非テーパー区間を **基礎 base(前40%) → 構築 build(40–80%) → ピーク peak(残り)** に分割
- 最後がテーパー taper、レース当日が race

---

## C. 距離とメニュー種別（各日に何を）— `plan.ts`

- **ロング走のピーク距離 `peakLong`** = ①レース距離由来（5K→10 / 10K→16 / ハーフ→20 / フル→32km、間は線形補間） と ②**安全上限「最長走×2＋2km」** の**小さい方**（急増による故障回避）
- **ロング走** = 開始時の最長走 → `peakLong` へ非テーパー週で線形に漸増、テーパーで ×0.7→0.55→0.4 に減量
- 各曜日の割当:

| 条件 | 種別 | 距離 |
|---|---|---|
| レース当日 | race | レース距離 |
| ロング走日 | long | その週のロング走距離 |
| quality日（構築/ピーク期のみ） | tempo | `0.6 × ロング`（3km〜`peakLong×0.7`） |
| その他の走る日 | easy | `0.5 × ロング`（2km〜`peakLong×0.7`） |
| レース週の走る日 | easy（軽め） | `0.4 × ロング`（2〜5km）。前日は休養 |

---

## D. ペース（@x:yy/km の決め方）— `paces.ts`

### 目標タイムを入れた場合（VDOT法 / Jack Daniels）

1. 目標(距離・時間) → **VDOT** を算出
2. VDOT から各ゾーンのペース:
   - イージー E = 70% VO2max
   - マラソン M = 84%
   - 閾値 T = 88%
   - 速い I = 100%（vVDOT）
3. 反映: イージー&ロング = E（フルのロングは M）、テンポ = T、**レース当日 = 目標ペース**

VDOT の式:
```
VO2(v)   = -4.60 + 0.182258·v + 0.000104·v²      (v: m/min)
%max(t)  = 0.8 + 0.1894393·e^(-0.012778·t)
              + 0.2989558·e^(-0.1932605·t)         (t: 分)
VDOT     = VO2(v) / %max(t)
```
ゾーンのペースは `VO2 = (%·VDOT)` を満たす速度 v を逆算して `pace = 60000/v` 秒/km。

### 目標タイム未設定の場合（現走力から近似）

- イージー = 推定イージーペース、テンポ = ×0.88、レース = ×0.85、ロング = イージー

### 所要時間と確保時間の上限

- 推定分 = `距離 × ペース ÷ 60`
- その曜日の `maxMinutes` を超えたら、**距離を縮めて時間内に収める**（`cappedByTime`＝「(時間調整)」表示）

---

## E. 伸ばし方・実現可能性 — `paces.ts buildProgression`

- 現VDOT → **現状での予測タイム**（VDOTの逆算 `predictTimeSec`）
- 必要短縮率 = `(予測 − 目標) / 予測`
- 実現可能性 = 残り週での妥当なVDOT改善 `min(0.35×週数, 現VDOT×0.12)` と、必要改善 `目標VDOT − 現VDOT` を比較:
  - 必要 ≤ 0 → 現実的（既に到達）
  - 必要 ≤ 妥当 → 現実的
  - 必要 ≤ 妥当×1.5 → 挑戦的
  - それ超 → 厳しい
  - 現VDOT不明 → 不明
- **達成保証ではない**ことを明示。

---

## F. ポイント練習（週1強調）— `plan.ts markKeyWorkouts`

各週で優先度が最大の練習を1つ ★（同点は距離大）:

```
レース(5) > インターバル(4) > テンポ(3) > ロング(2) > イージー(1)
```
→ 構築/ピークはテンポ、基礎はロング、レース週はレースが「今週のポイント」になる。

---

## G. スキップ・再計算（決定的）

- `generatePlan` は入力だけで決まる純粋関数。`skippedDates` の日は休養化。
- 日/週スキップ = 対象日を `skippedDates` に追加 → 再導出で休養に。
- 再計算（今日起点）= `startDate` を当日に更新して再生成（CSV更新での走力変化も反映）。

## I. 心拍(HR)・VO2max の利用 — `heart-rate.ts` / `fitness.ts`

CSV の `平均心拍数`/`最大心拍数` を使う（Strava 不要。CSV に既にある）。
- **最大HRの自動検出** `observedMaxHr`: 取り込んだ活動の最大心拍の最大値。
- **HRゾーン** `hrZones`(%HRmax 5ゾーン): Z1 50-60% / Z2 60-70% / Z3 70-80% / Z4 80-90% / Z5 90-100%。
  各練習に推奨ゾーンを併記（easy=Z2, long=Z2, tempo=Z4, interval=Z5, race=Z4）。
- **現状VDOT推定の精度UP** `estimateCurrentVdot(…, maxHr)`: 最大HRが分かるとき、
  `avgHr ≥ 80%HRmax` の「本当に追い込んだ走」だけを VDOT 推定に採用（過小/過大を低減）。
- **推定VO2max** = VDOT（有効VO2max）。UI のサマリと「目標と伸ばし方」に表示。
- 注意: VO2max は数値では取得できない（Strava/CSV とも）ため**推定**。最大HRは実測テスト無しの**観測値**で近似。

## 注意

- 自動生成は一般的なヒューリスティック（VDOTは確立モデルだが個人差大）で、**医学的・専門的助言ではない**。体調に応じて調整前提。
- 現VDOTは練習走ベースで控えめに出やすい → 予測は保守的。
- 設定はブラウザ（localStorage `flrt:training:v1`）に保存。端末/ブラウザ間で共有されない。
