# Strava Bulk Uploader (Chrome 拡張)

指定フォルダ内の `.fit` / `.tcx` / `.gpx`（`.gz` 含む）を、Strava の内部アップロードエンドポイント
（`POST /upload/files`）へ**ブラウザのログインセッションのまま直接 POST** して一括アップロードする Chrome 拡張。

> 大量移行には `tools/strava-api-uploader/`（公式 API ＋ Node CLI）の方が枠が大きく安定します。
> 本拡張はブラウザだけで完結させたいケース向け。Web の一括アップロードには件数上限があり、
> 上限に達したら自動で待機して再開します（後述）。

## インストール

1. このフォルダ（`manifest.json` がある場所）を任意の場所に置く
2. Chrome で `chrome://extensions` を開く
3. 右上の「デベロッパーモード」をオン
4. 「パッケージ化されていない拡張機能を読み込む」→ このフォルダを選択

## 使い方

1. `https://www.strava.com/upload/select` を開く（ログイン済みであること）
2. 右上のパネル（ドラッグで移動可）の「フォルダを選択して開始」を押す
3. フォルダを選ぶ → あとは放置。`成功 / 重複 / 失敗 / 時間切れ` のカウントが進む
4. 完了すると「🎉 完了」。`結果をDL` で TSV ログを保存できる

## 仕組み

- フォルダは **File System Access のディレクトリハンドル**で保持し、各ファイルは送る直前に読む
  （IndexedDB への全コピーをしないので**ディスクを消費しない**）。
- 各ファイルを `POST /upload/files`（`files[]` を最大 `BATCH_SIZE` 件まとめて）→ `GET /upload/progress.json`
  で 成功/重複/エラー を確定。**ページ遷移しない**。
- `content_scripts` は `world: "MAIN"` でページと同じ実行コンテキスト（CSRF トークン・Cookie をそのまま利用）。
- 成功・重複したファイル名は `localStorage`（`sbu2_done_v1`）に記録し、**再実行時は自動スキップ**。
  タブを閉じても、同じフォルダを選び直せば続きから。

## レート制限（上限到達時）

Web の一括アップロードには件数上限があり、超えると `429` と「アップロードの最大数を超えました」が返る。
本拡張は上限を検知すると `QUOTA_WAIT_MS`（既定 10 分）待って**自動で再試行**し続ける（中断ボタンで停止可）。
`Retry-After` 付きの一時的スロットルには指数バックオフで対応する。

## 調整ポイント（`content.js` 冒頭の定数）

| 定数                 | 意味                                        |
| -------------------- | ------------------------------------------- |
| `BATCH_SIZE`         | 1 リクエストに載せるファイル数（上限 25）   |
| `CONCURRENCY`        | 同時に走らせるバッチ数（多いほど 429 誘発） |
| `POLL_INTERVAL`      | 進捗ポーリング間隔                          |
| `POLL_TIMEOUT`       | 1 ファイルの最大待機                        |
| `POST_RETRY`         | 一時的失敗（RA 付き 429 / 5xx）の再試行回数 |
| `REQUEST_SPACING_MS` | 全リクエスト共通の最小間隔                  |
| `QUOTA_WAIT_MS`      | 上限到達時の待機時間（自動再試行の間隔）    |

## 注意

- **専用タブ推奨**：実行中はそのタブを開いたままに。
- セレクタ等は Strava の DOM/エンドポイント依存。仕様変更で動かなくなったら定数・実装を更新する。
- 重複は Strava が弾くので、何度実行しても二重登録されない。
